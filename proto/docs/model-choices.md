# Model log

Which model each worker ran on, for what kind of task, and how the result held up. Started 15 Nov 2026 at Paul's request, so that model choice is made on evidence rather than habit. The coordinator updates it when a worker is started and again after its work is reviewed.

## Usage pools (Paul, 15 Nov 2026)

- **Cursor's own models: Grok 4.7, Grok 4.6, Composer 2.5.** Plenty of room (13% used on 15 Nov, resets 5 Dec). Use freely.
- **Everything else (Fable, Opus, Sonnet, GPT, Gemini, Muse).** Limited. The limit was hit on 15 Nov and raised once. Use only where it earns its place.

## The list (agreed with Paul, 15 Nov 2026, to be followed without exception)

Every worker gets a model from this table, set on purpose. The model is named when a worker starts or changes model; follow ups to a worker already on the right model leave it out, because a message that names a model is only read when the worker's turn ends (Paul agreed, 15 Nov 4:43 PM). Every tracker task carries a tag for the model that built it, and every worker is a row in the log below.

Change (Paul, 16 Nov 1:21 AM): worker jobs that went to Fable now go to Opus 5.5 to save usage, at the same effort level (high for hard logic, design and planning workers; medium for reviews). The coordinating chat itself stays as Paul sets it. Rows below that name Fable for a worker read as Opus 5.5.

| Task type | First pick | Alternative |
|---|---|---|
| Coordinating, planning, judging reviews | Fable 5.2 high (the coordinating chat); planning workers Opus 5.5 high | none |
| Hard logic with interacting rules (silent, expensive mistakes) | Opus 5.5 high | Grok 4.7 xhigh, to be trialled on the next hard job |
| Well specified build with a clear pass or fail | Grok 4.7 high | Composer 2.5 |
| Mechanical work (small fixes, screenshots, searches, pulling the Surface) | Composer 2.5 fast | Grok 4.6 low |
| Independent review and naive user pass | Grok 4.7 high when the builder was Opus (a different family) | Opus 5.5 medium when the builder was Grok or Composer |

Handoff rule: on a hard logic job, Fable writes the rules and the code that depends on them, checks the rules with fast script checks, and writes a handoff. The long browser proving, screenshots and screen fixes go to Grok 4.7. A fault in the rules returns to Fable as a small, narrow job.

These picks are starting bets from reputation. The log below is what turns them into evidence. The aim is to move work down to the Cursor pool wherever the log shows quality holds.

Also: start a fresh worker for a new job unless it truly needs an old worker's setup. A long lived worker carries its whole history into every step.
