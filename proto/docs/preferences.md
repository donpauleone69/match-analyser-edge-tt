- **Match hub:** Tabs: Insights · Details · Tag (header names the match; no heading repeats a tab). New and open existing both enter Match; no Create page. A match opens by state: no video or untagged on Tag (Videos live in Tag since v0.9), tagged on Insights. Tag lands on a per-set checklist; a set opens one player with rallies and their shots plus the tagging steps (contacts, key moments, shot details, extras, save, next rally). Details holds the result and set scores as one area: the result dictates the set count (3 - 2 means 5 sets), scores are entered and should agree with tagging, and a mismatch is flagged. Video is per match: an ordered, sequential list with no mapping of sets to videos. "Not filmed" means only that the user chose to skip a set. Adding a video from Tag must not bounce the user to Details and strand them. Insight sections are a pill switch inside the page, never a second row of tabs. (updated 2026-11-17)
- **Tagging method:** The real app's Pass 1 (contact tapping, then tagging, one quick pass per rally while watching, with automation) is sound and is the guide for logic and function. - **Tagging tolerates real-world mistakes:** Do not handle each edge case (wrong score, point to the wrong player, four serves in a row) on its own; build one system that allows for them. Server is worked out from the score but is easy and clear to switch while tagging; what was tagged is kept, add or delete must keep continuity, and continuity errors are highlighted rather than fixed by switching servers in the Rallies list. Lets are dropped. A rally starts 2s before the serve contact. Swap players is offered only on a rally the continuity check has marked. Nothing extra to press while tapping: result buttons live during the rally were tried in an earlier build and the game is too fast for it, so the idle close stays. (2026-11-15)
