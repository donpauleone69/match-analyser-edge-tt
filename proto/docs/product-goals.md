# Product goals — user wants (Match Analyser)

Updated: 2026-11-13 (Europe/London). Source: Paul. Keywords: **usability · speed · accuracy · intuitiveness**. Targets: **phone · iPad · Windows**.

Replace thin “core loop” wording with these user wants. Agents plan and build toward them.

## User wants

1. **Tag my matches** — fast, accurate Pass 1 tagging.
2. **Add context when there is any** — opponent, tournament, date, etc., optional not forced.
3. **Curated data + stats + video playlists** that identify strengths, weaknesses, areas to improve; **downloadable videos** to see what works / doesn’t and to show coaches.
4. **Intuitive navigation** — tagging, reviewing, editing tags, finishing incomplete jobs, adding context — one coherent flow, little menu diving or constant scrolling.
5. **Find matches seamlessly** — by list, date tagged, match date, tournament, opponent, etc.
6. **Patterns across matches** — not only sequential watch of one match (e.g. pressure 9–9 → more defensive / more first-attack errors). Insights must lead to playlists.
7. **Real tournament capture reality** — long intro, warm-up, gaps between sets, long tail; jump to first serve / between sets; player ready fast; trim + archive/compress so original can be deleted.
8. **Resume** — pick up where left off; see what’s outstanding.
9. **Incomplete rallies/points excluded from stats** — don’t skew analysis.
10. **No duplicate tagging** of the same match.
11. **Edit / re-review** old tags to fix mistakes and improve accuracy.
12. **Future (later):** scout opponents; pro-game benchmarks from basic tagging (data TBD).

## Design principles (from above)

- Insights → playlists → optional download (not dead-end numbers).
- Phone-first chrome; iPad/Windows must stay usable.
- Less is more; outstanding work and resume must be obvious.
- Video lifecycle is part of the product (navigate dead air, trim, archive), not an afterthought.
